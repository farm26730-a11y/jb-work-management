- `근태` 탭에 연차 발생·사용·잔여일수(확정 범위) 표시, 직원 입사일·월별 개근 및 근속 연차 확인 기능 추가
- **운영 Supabase에 연차 전용 스키마와 RPC 설치 완료**: 기존 직원 데이터 유지. 실제 계정 화면·쓰기 테스트는 아직 미완료. GitHub main/Netlify 운영 UI 미변경
- 운영 Supabase 설치 SQL 보관본: [연차관리 SQL](development/2026-11-14/JB_V1_3_입사일기준_연차관리_설치전검토.sql)
- 구현·검증 상태: [연차 관리 설계 및 시험](development/2026-11-14/JB_V1_3_입사일기준_연차관리_설계및시험.md)
- 연차 인사 장부 3개는 별도 `jb_hr` 스키마에서 보존. 기존 운영 기록 초기화는 21개/보존 8개 범위 그대로 유지
- 개근·80% 출근율은 별도 확인 필요. 근태 기록만으로 확정 권리를 자동 계산·차감하지 않음

- 개발 환경 규칙: GitHub `development-test`에서 수정·시험, Supabase 운영 프로젝트의 데이터로 개발하되 운영 DB 변경은 기존 앱에 즉시 영향을 줄 수 있음

## 2026-11-14 추가 검증: 연차 조회·승인 확인

- 기존 `근태 → 휴무·연장근무 조회`에 **휴무·연장근무 내역 / 연차 조회** 탭 추가. 별도 상단 연차 섹션은 제거
- 운영 Supabase의 **연차 전용 RPC만** 개선: 발생 미확정/0일 구분, 한국 날짜, 사용일수 재확인, 승인 사유 감사
- 승인된 직원 연차/반차는 개발 화면에서 최신 잔액 사전 확인 후 서버의 신규 래퍼 RPC를 호출. 기존 운영 승인 함수 수정 없음
- 근로일 및 이전 발생분 확인이 없는 경우 자동 차감/거부 대신 관리자 확인 요구
- 기존 승인 휴무의 종류 변경은 백엔드 불일치 우려로 직원 변경 신청에서 막고 취소 후 재신청 안내
- 실제 실계정 승인·갤럭시 시험 미완료, **운영 main/Netlify 변경 금지**
- 기록: [개발 및 남은 위험](development/2026-11-14/JB_V1_3_입사일기준_연차관리_설계및시험.md)

## 운영 적용 전 절차

1. 운영 `main` 최신 커밋과 시험본의 차이를 검토
2. Supabase 필수 SQL / RLS / 권한 확인 (계정별 실제 기능 테스트는 별도)
3. 갤럭시에서 직원·관리자·대표 계정별 댓글·업무·식사·푸시 테스트
4. 검증 완료 후 **명시적인 운영 배포 결정**에 따라 `main`에 병합
5. Netlify 운영 배포 상태와 알림 기능 확인

**주의:** SQL 설치 여부와 앱 기능 정상 작동 여부는 별개입니다. 이 브랜치의 최신 코드가 운영에 배포되었다고 간주하지 마세요. 사용자 정보나 비밀 키를 저장소에 올리지 마세요.
