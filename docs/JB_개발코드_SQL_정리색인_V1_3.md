> 작성 기준: 2026-11-07 / **운영 서버에 적용하지 않은 정리 전용 브랜치**
>
> **중요:** 이 문서는 GitHub에 있는 파일을 분류한 것이며, Supabase 실제 DB에 어떤 SQL이 실행되었는지 단정하지 않습니다.

## 1. 환경과 수정 규칙

- GitHub 저장소: `farm26730-a11y/jb-work-management`
- 운영 브랜치: `main` (**직접 수정 금지**, 자동 배포 연결 가능)
- 정리 작업 브랜치: `maintenance/sql-inventory-readonly-v13`
- 통합 시험 기능 브랜치: `feature/meal-dinner-cutoff-setting-v13` (식사/고정 인원/저녁 마감/픽토그램)
- 운영 앱 표시 버전: **V1.3 유지**
- 식사 기능 SQL은 독립 파일로 관리하되, 선행 설치 순서를 지키며 운영 DB 적용 전 별도 검증
- 기존 SQL 파일의 수정·이동·삭제 없음. 특히 `CREATE OR REPLACE FUNCTION`, `DROP POLICY`, `DROP TRIGGER`는 다시 실행하면 동작이 바뀔 수 있어 조회 전용이 아님
- **조회용 SQL은 `SELECT` 중심으로 작성**. `SELECT public.변경함수(...)`는 DB를 바꿀 수 있으므로 조회용이라고 부르지 않음
- 서비스 역할 키, API 비밀키, 사용자의 이메일·전화번호를 GitHub 파일에 저장하지 않음

## 3. SQL 용도 구분 표준

- `[조회용]`: SELECT, 시스템 카탈로그 조회, 테이블/함수 존재 확인. **변경 함수 호출 금지**.
- `[설치용]`: CREATE TABLE, ALTER, CREATE OR REPLACE FUNCTION, CREATE/DROP POLICY, CREATE/DROP TRIGGER, GRANT/REVOKE 등. 검증 후 실행.
- `[수정용]`: UPDATE/INSERT/DELETE, 데이터 보정, 실제 비즈니스 함수를 호출하는 SELECT. 운영 데이터 변경 가능.
- `[과거/참고]`: 이전 버전, 미사용 가능성 또는 실제 운영 상태 미확인. 절대 즉시 재실행하지 않음.
- `[삭제용]`: DROP TABLE/FUNCTION 등. 사전 백업과 의존성 확인, 명시적 승인 없이는 실행하지 않음.

## 5. 앞으로의 코드 정리 방법 (미시행)

현재 `index.html`은 HTML/CSS/JavaScript가 하나로 묶여 있습니다. 단순 함수 선언명 정적 검사에서 **동일 이름이 2번씩 등장한 함수 4종**: `archivePage`, `noticeCanEdit`, `rosterEditor`, `saveEvent`. 다만 HTML에는 여러 스크립트와 과거 구현이 함께 있을 수 있으므로 선언 위치·실제 호출 경로·런타임 우선순위 확인 전에는 오류 또는 미사용으로 단정하지 않습니다. 지금은 업무·휴무·보고·인원배치와 연관된 코드를 이동하거나 삭제하지 않습니다.

추후 안전하게 분리할 경우, 기능별 모듈 + 공통 유틸리티, DB 함수/트리거 이름 목록, 테스트 시나리오, 변경 기록을 분리해 관리합니다. 단, 함수명 중복이나 과거 구현이라는 이유만으로 삭제하지 않습니다.

## 6. Supabase SQL Editor 정리 방침

SQL Editor에서 저장한 쿼리는 GitHub 파일과 별개입니다. PostgreSQL 일반 쿼리로 **SQL Editor 저장 목록 전체를 읽을 수 있다고 가정하지 않습니다**. SQL Editor 목록을 보고 제목을 `[조회] 기능명`, `[설치] 기능명`, `[과거] 기능명` 등으로 정리하고, 기존 사용자가 저장한 쿼리는 먼저 백업합니다. **실제 Supabase DB의 함수/테이블/트리거는 SQL Editor 쿼리를 삭제해도 자동 삭제되는 것이 아닙니다.**
