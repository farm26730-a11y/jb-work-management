# 사진 포함 업무 보고 배포 검토

## 적용 전 확인

- 운영 프로젝트 bnonnvgtbukztfhaxgrr의 기존 보고 함수 정의와 ACL을 보관한다. 앱 배포 SHA와 직전 정상 Netlify 배포 ID도 기록한다.
- report-comment-id-install.sql은 확인한 운영 함수 정의와 현재 정의가 달라지면 중단한다. 사진 포함 보고용 함수 한 개를 추가하며 기존 보고 함수의 반환값, ACL, 테이블 및 정책은 유지한다.
- 새 함수는 로그인 UID에 연결된 활성 직원이나 부서장인지 확인하고, 본인 담당 또는 작성 업무로 제한한다. 기존 보고 코어와 같은 트랜잭션 잠금, 댓글 INSERT, 보고 요청 갱신, 푸시 대기열을 사용하고 해당 INSERT의 ID를 반환한다. 기존 코어에 대한 직접 실행 권한을 확대하지 않는다.
- 새 함수와 기존 코어의 보고 규칙은 향후 변경 시 함께 검토한다. 실제 사진 업로드는 별도의 Storage 및 사진 레코드 정책을 따른다. 운영의 타인 업무 댓글 사진 권한 확대는 이 SQL의 범위 밖이며, 필요 시 정책을 별도 검증하고 승인한다.

## 승인 후 적용

1. 운영 SQL 적용과 운영 프런트엔드 배포를 각각 명시적으로 승인받는다.
2. JB-DEV에서 테스트 계정으로 보고·사진 업로드·알림을 확인한다.
3. 승인받은 운영 SQL을 실행한다. 함수 시그니처와 로그인 역할 실행 권한, 익명 접근 거부 및 API 스키마 반영을 확인한다.
4. 승인받은 프런트엔드 버전을 배포한다.

## 복구

1. 문제 발생 시 프런트엔드를 직전 정상 배포로 되돌리고, 기존 보고 경로를 확인한다.
2. 운영 DB에서 새 RPC를 호출하는 앱이 남아 있지 않은지 확인한 뒤, 별도 승인에 따라 report-comment-id-rollback.sql을 적용한다.
3. 새 함수 제거 후 기존 함수 정의와 ACL을 다시 확인한다. 기존 업무·댓글·사진·보고 및 알림 대기열 데이터는 보존된다.
