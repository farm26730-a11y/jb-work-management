# JB 업무관리 앱 개발 기능 대조

기준은 GitHub의 `development-test` 9f60576, 최신 사진 수정본 `fix/jb-comment-photo-20261122` 40e3f5c, 운영 `main` 4ef6354다. 세 브랜치의 실행 HTML과 앱 디렉터리 전체 파일을 대조했다. 개발과 운영의 이력이 갈라져 있어 커밋 제목만으로 구현 여부를 판정하지 않았다. 배포 후보와 공식 개발본 사이에 차이가 있는 실행 파일은 index.html과 Netlify 설정·함수 파일 4개였다. 과거 작업 문서·시험 SQL·백업 HTML은 실행 기능과 구분했다.

## 기능별 대조

| 기능 | 분류 및 결과 |
|---|---|
| 홈 제목·업무 등록 | **누락 → 복구.** 공식 개발본의 jb-home-titlebar와 권한 조건을 복원했다. 기존 버튼 이벤트로 업무 탭 전환, 편집기 열기, 제목 입력 포커스를 확인했다. |
| 홈 업무·확인 현황, 직원별 목록 및 상태 | **동일 기능 유지.** 예정·보류·진행중·완료·확인 요청, 직원별 조회 및 상태 권한 로직이 있다. 사진 수정본의 상세 카드 스타일과 안내는 유지했다. |
| 등록·반복 양식 | **다른 구현 유지.** 예정/진행중 등록, 업무 사진·보고 옵션, 개인 양식 격리는 유지한다. 후보의 최근 버튼 배치와 조회만 하는 양식 새로고침, 입력 초안 보존을 유지했다. |
| 업무 수정·삭제·시간 이력 | **동일 기능 유지.** 제목·설명·사진 및 이력, 수정·삭제 권한 조건과 상태 드롭다운을 유지한다. 최신 후보의 배치·표시는 공식 개발본과 차이가 있다. |
| 완료 보관함과 모바일 UI | **동일 기능 유지.** 7열 달력, 색상 대비, 시간·사진·댓글 조회를 유지한다. 개발 DB의 완료 상태 잠금 트리거는 운영 배포 후보에 포함하지 않았다. |
| 댓글·업무 사진·촬영·삭제 | **다른 구현 유지.** 사진만 등록과 기존 댓글에 추가 기능을 유지한다. 후보는 댓글 전용 경로, 파일 정리, 부분 실패 안내, 재렌더링 뒤 버튼 복원 및 업로드 구분을 보강했다. |
| 상급자 확인·대표 직접 보고 | **다른 구현 유지.** 텍스트 보고는 기존 RPC, 사진 포함 보고는 실제 댓글 ID 반환 RPC를 사용한다. 운영 RPC 적용과 JB-DEV에서의 호환 RPC 검증은 아직 필요하다. |
| 확인 요청·알림 | **동일 기능 유지.** 신규 업무·댓글·보고·승인 확인, 알림 읽음과 즉시 푸시 요청/예약 발송 경로를 유지한다. 후보의 VAPID 안내·설정 표시 차이는 운영 호환을 위해 유지했다. |
| 로그인·가입·계정 연결 | **부분 누락 → 복구.** 이메일 가입과 활성 직원 연결, 부서장·대표 관리, 권한 유효성 확인은 유지돼 있었다. 개발본 대비 직원 관리 자동 갱신과 20초·포커스·화면 복귀 갱신을 복구했다. 직원 관리 수동 갱신은 연결 장애 후 재시도를 위해 유지했다. 변경 없는 응답과 입력 중에는 화면을 다시 그리지 않는다. |
| 로컬 가입 요청 경고 | **오류 → 수정.** 파일 URL에서는 기존 함수가 요청을 보내기 전에 예외를 냈고, 갱신 코드가 이를 가입 요청 실패로 표시했다. JB-DEV 미리보기는 파일이나 HTTP로 열어도 같은 제한을 표시하고 호출을 생략한다. HTTPS 배포에서는 기존 account-admin 함수 호출을 유지한다. |
| 근태·인원배치·휴무·연차 | **동일 기능 유지.** 전날 배치 복사, 임시 인원, 근태 저장, 휴무·변경 승인, 입사일 자동 산정 및 수동 차감 코드가 있다. 후보는 운영의 잠정 연차·중복 차감·서버 점검 설명을 유지했다. |
| 식사·공지·일정 | **동일 기능 유지.** 식사 마감, 달력, 고정·외부 인원, 공지 입력과 일정 코드가 일치하거나 안내 문구만 다르다. |
| 직원·부서 권한 | **동일 기능 유지.** 대표·부서장·직원의 조회·등록·관리 분기와 운영의 비활성 직원 보호. 역할이 바뀌면 가입 목록도 비운다. 실제 계정별 RLS 검증은 별도다. |
| Netlify Functions·PWA | **의도적 제외.** 개발 전용 noindex, JB-DEV 주소 제한을 운영 호환 앱에 복사하지 않았다. account-admin·public-config·push-core의 차이는 환경 제한이며, push-now/dispatch/config, Service Worker, manifest는 동일하다. 동봉한 미리보기는 JB-DEV 주소에 고정한다. |
| 기록 초기화·데이터 보호 | **동일 보호 유지.** 대표 전용 초기화 버튼은 비활성화. 후보는 운영 백업·보존 항목 안내를 유지했다. 개발 SQL 이력의 변경을 이 브랜치에 자동 실행하거나 옮기지 않았다. |
| 그 외 과거 문서·SQL·중간 UI | **의도적 제외.** 이전 4상태 버튼은 공식 최신본에서 드롭다운으로 돌아갔다. 개발 전용 기록과 SQL은 개발 브랜치에서 확인하며 별도 DB 적용이 필요하다. |

## 브라우저 검증 및 한계

- 통과. Chromium 1280px·393px에서 홈 제목 오른쪽의 등록 버튼, 클릭 후 업무 탭·편집기 및 제목 포커스를 확인했다. [PC](home-pc-1280.png) · [모바일](home-mobile-393.png)
- 통과. 모의 HTTPS에서 직원 관리가 account-admin을 호출하고, 정적 미리보기에서 홈·직원 관리 안내가 나오면서 요청이 0건임을 확인했다. 앱의 모의 DB·Storage를 사용해 등록·반복 양식·댓글·사진·보고·초안·버튼 복원을 양쪽 너비에서 재실행했다.
- 공개 URL 읽기 전용 확인에서 운영은 HTTP 200, 개발 Netlify는 HTTP 401이었다. 두 사이트의 실제 로그인, 직원 등록·연결, 연차·식사 저장, Storage·푸시 수신은 미검증이다. 브라우저 폭 시험은 실기기 시험과 구분한다.
- [실행 HTML](jb-dev-preview.html)을 내려받아 열고 JB-DEV Publishable Key와 개발 계정을 사용한다. 브라우저 API 연결은 JB-DEV만 허용한다. 로컬 가입 요청·계정 연결 및 Netlify 푸시는 지원하지 않는다.

**판정: 운영 배포 보류.** 사진 포함 보고 RPC·실제 Storage 및 역할별 가입 연결·푸시는 승인된 테스트 환경에서 검증해야 한다. main, 운영 Supabase, Netlify에 변경을 적용하지 않았다.
