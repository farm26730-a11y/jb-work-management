# JB 업무관리 V1.3 — 회원가입 요청 관리자 홈 연결 보완

기록일: 2026-11-13
개발 브랜치: `development-test`
운영 브랜치: `main` (변경하지 않음)

## 이전 채팅방 요구사항 반영
- 로그인 화면은 이메일 회원가입 → 인증메일 확인 → 관리자/대표 직원 연결 → 직원 로그인 순서 유지
- 신규 가입자와 기존 직원 기록을 연결하되 업무·근태 기록 보존
- 연결되지 않은 가입 계정의 삭제·재연결 기능은 기존 직원관리 계정 관리 기능 유지
- 관리자/대표 홈의 확인 요청에서 신규 가입 계정 상태 확인 및 바로 연결
- 직원에게 계정 관리 목록 노출 금지; 서버에서 사용자 JWT와 직원 권한 재검사

## 코드 수정
1. `index.html`
   - 운영자 홈 `확인 요청`에 미연결 Supabase Auth 가입 계정 표시 (최대 7개 보이는 요약은 기존 위젯 규칙을 따름)
   - 가입일 및 이메일 인증 상태 표시; 이메일 미인증 상태는 연결 버튼을 제공하지 않음
   - 인증된 계정은 `기존 직원 연결` 또는 `신규 직원 등록`을 선택
   - 기존 직원 연결 전에 이메일, 직원 이름·직급·부서 확인
   - 신규 직원 등록 시 이름·직급·부서를 입력, 기존 `jb_link_staff_by_email_v24` RPC 사용, `staff` 역할만 요청
   - 첫 로그인 뒤 가입 요청 조회, 홈이 표시된 상태에서 60초 간격 확인, 수동 새로고침
   - 계정 조회 오류 표시와 입력 폼 편집 중 불필요한 자동 새로고침 방지
   - 직원관리의 미인증 계정 연결 버튼도 숨김
2. `netlify/functions/account-admin.mjs`
   - `availableEmployees`에 `department_id` 포함해 동명이인 오연결을 피하기 쉽게 함
   - 기존 서버 JWT/직원 역할 재검사 및 UID 중복 링크 보호 동작 유지

## 권한 및 데이터 원칙
- 계정 조회와 기존 직원 연결/재전송: 로그인한 `owner`/`manager`만
- 신규 직원 등록: DB의 `jb_link_staff_by_email_v24`가 다시 확인; `staff`로만 등록
- 이메일 인증이 없는 계정은 연결 금지
- 기존 직원 기록의 ID, 업무/근태 이력을 유지하고 `auth_user_id`만 연결
- `jb_employees.auth_user_id`는 운영 DB에서 UNIQUE 인덱스 확인
- Service role 키는 Netlify 서버 환경변수에서만 사용; 프런트엔드에 삽입하지 않음
- DB SQL 변경 없음. 운영 DB에는 SELECT로 함수 정의/인덱스 조회만 수행

## 자동·정적 점검 (실시)
- 전체 HTML 내 4개 실행형 인라인 스크립트 구문 검사: 통과
- 관리자 전용 가입 계정 표시, 이미 연결된 계정 제외, HTML 이스케이프, 이메일 인증 전 연결 차단: 모의 시험 통과
- 신규 일반 직원 RPC 인자, 성공 후 연결 재조회, 미인증 호출 차단: 모의 시험 통과
- Netlify `account-admin` 실제 HTTP 호출과 DB 데이터 변경을 수반하는 통합시험은 수행하지 않음
