# 업무 진행 시간 검증

## 실행

저장소 루트에서 Node.js 24를 사용합니다. 브라우저 시험에는 Playwright와 Chromium이 필요합니다. Playwright는 Node에서 `playwright/test`를 찾을 수 있어야 하며 Chromium 기본 경로는 `/usr/bin/chromium`입니다.

```sh
node --test development/task-clock/unit.cjs
node development/task-clock/browser.cjs main
node development/task-clock/browser.cjs
```

`main` 인자는 운영 기준 커밋 `4ef6354`의 HTML을 격리된 Chromium에 로드합니다. 인자가 없으면 현재 체크아웃을 읽습니다. 두 모드 모두 Supabase 인증과 상태 RPC의 응답을 가상 데이터로 제공합니다. 운영 서비스나 DB에 연결하지 않습니다.

## 읽기 전용 감사

[`audit-read-only.sql`](audit-read-only.sql)은 승인된 전체 업무·이력 읽기 권한이 있는 PostgreSQL 세션에서 운영 수치를 집계합니다. RPC·트리거·정책 정의를 읽으며 상태 RPC 호출이나 복구를 수행하지 않습니다. 권한에 따라 보이는 행만 집계되는지 먼저 확인해야 합니다.

동일 담당자의 현재 복수 진행과 과거 진행 구간 중첩은 자동 보류 누락을 조사할 후보입니다. 과거 담당자가 변경됐거나 제외 정책이 있으면 별도 증거가 필요합니다. 중복·누락 후보의 복구는 원본 트랜잭션·업무 기록으로 정확한 시각과 전환을 입증하고 별도 승인된 뒤 검토합니다.

운영 반영 전 JB-DEV에서 같은 빌드의 시간 함수와 Supabase 시각 차이를 비교하고, 실제 역할 계정과 격리 업무로 상태 RPC·트리거·동시 처리·저장·RLS를 확인합니다. 새 시간 함수에 연결할 수 없으면 브라우저 시각으로 열린 구간을 계산합니다. 이미 끝난 구간은 계속 기록된 두 시각으로 계산합니다.
