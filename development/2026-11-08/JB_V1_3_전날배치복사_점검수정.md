# JB 업무관리 V1.3 — 전날 배치 복사 기능 점검·수정

점검 기준: 2026-11-08 운영 Supabase DB 스키마와 GitHub 시험용 `index.html`. 운영 DB 수정 없음.

## 실제 확인한 오류
1. 기존 구현은 전날 임시 인원을 무조건 `id:null`로 복사해 저장 시 새로 INSERT. 오늘 같은 이름의 임시 인원이 이미 있으면 중복 데이터 생성 위험.
2. 오늘 저장된 임시 인원 중 전날 명단에 없는 인원은 복사 초안에서 빠지지만 DELETE 작업이 생성되지 않아 DB에는 남는 문제.
3. 전날 저장 기록이 없는 일반 직원도 `status:'working'` 초안으로 바뀌고 `changed:true`가 되어 저장 시 불필요한 기본 출근 배치 생성.
4. 기존 로직은 전날의 추가 작업 안내까지 덮어씀. 오늘 이미 작성한 안내가 예고 없이 교체될 수 있음.
5. 기존 확인창은 입력 중일 때만 표시되어 오늘 저장된 인원이 대거 교체·삭제될 수 있다는 점을 충분히 알리지 않음.

## 시험 브랜치 수정 내용
- 전날 원본 `jb_attendance` 기록만 조회해 복사 (계산된 근태 VIEW의 자동 휴무 상태를 재사용하지 않음).
- 같은 이름의 오늘 저장 임시 인원은 기존 UUID 보존 + UPDATE, 전날에 새로 나온 이름은 INSERT.
- 오늘에만 저장돼 있던 임시 인원은 `_delete:true`로 표시해 최종 저장 시 DELETE RPC 작업을 생성.
- 전날 기록이 없는 정규 직원은 오늘 저장된 값을 유지 (임의로 기본 출근 처리하지 않음).
- 날짜별 현재 승인된 종일 휴무는 우선 적용.
- 오늘의 ‘추가 작업 안내’는 유지하며 전날 안내를 자동 복사하지 않음.
- 저장된 데이터와 저장 전 임시 입력이 영향을 받을 수 있음을 사전 확인창에서 설명.
- 전날 임시 인원 이름 누락/중복, 오늘 저장된 임시 인원 동명이인으로 판단될 위험이 있는 중복 데이터는 자동 복사를 중단.
- 사용자가 취소하거나 전날 기록이 없으면 현재 초안을 변경하지 않음.
- 최종 **'이 날짜 인원배치 저장'** 버튼을 눌러야 DB가 변경되는 기존 흐름과 `jb_save_attendance_batch` RPC는 그대로 유지.

## 정적·모의 검증
- 전체 HTML 내 스크립트 블록 4개: `new Function` 정적 문법 검사 통과.
- JS 의존성 모의 시험: 전날 정규 1명, 임시 2명 / 오늘 정규 2명, 임시 2명.
  - 전날 정규 직원 상태가 복사됨(오늘 승인 휴무 시 `off` 우선).
  - 전날 기록 없는 오늘 직원은 기존값 유지.
  - 이름 같은 임시 인원은 오늘 UUID 유지.
  - 전날 신규 임시 인원은 `id:null`로 추가.
  - 오늘에만 있던 임시 인원은 `_delete:true`.
  - 오늘 추가 작업 안내 보존.
  - 확인창 취소 시 초안 유지.
  - 전날 배치 0건이면 초안 유지.
- 운영 Supabase 일자별 건수 확인: 2026-11-08 정규 7 / 임시 4, 2026-11-09 정규 7 / 임시 4. 확인만 했으며 데이터 변경 없음.
- **실제 Galaxy UI / 실계정 RPC 저장 테스트는 실시하지 않음.**

## 실제 테스트 체크리스트
- [ ] 전날 임시 2명 중 오늘과 같은 이름 1명: 저장 후 중복 없이 한 행으로 업데이트
- [ ] 오늘에만 있는 임시 인원: 복사 예고창에서 삭제 건수 표시 → 저장 후 사라지는지
- [ ] 전날 기록 없는 정규 직원: 오늘 상태 유지
- [ ] 오늘 승인 휴무: 복사 후에도 `off` 유지
- [ ] ‘추가 작업 안내’: 전날 문구로 덮어쓰지 않는지
- [ ] 저장 전 복사 취소: 기존 임시 입력과 장소가 그대로인지
- [ ] 저장 후 다른 갤럭시에서 새로고침해 동일한 배치가 표시되는지
- [ ] 두 번 연속 복사/저장해도 임시 인원 수가 늘지 않는지
- [ ] 근무 장소가 없는 출근 인원은 저장 전에 안내되는지
