# JB 업무관리 V1.3 — 업무 보고 푸시 알림 즉시 발송 시험 수정

## 요청
보고 등록 시 알림을 댓글처럼 빠르게 보냅니다.

## 원인
기존 운영 및 시험 코드에서 보고 요청은 Supabase `jb_task_report_requests` INSERT / `jb_submit_report_core_v14` RPC를 통해 `jb_push_outbox`에 `report` 타입으로 기록됩니다. 그러나 기존 빠른 전송 요청 `push-now`는 `task`, `comment`만 지원했습니다. 예약 발송은 매분 1회입니다.

## 이번 변경
- `index.html`: 새 업무 등록 후 보고, 업무 내용 수정 후 보고, 댓글에서 상급자 확인 요청 또는 대표님 직접 보고 시 서버 RPC 성공 후 `jbWakeServerPush('report', taskId)` 비동기 호출
- `netlify/functions/push-now.mjs`: `report` 허용 및 Bearer 세션으로 인증된 활성 직원의 해당 업무 보고인지 확인. 실제 보고 요청과 2분 이내 본인 작성 댓글의 내용 일치 여부를 검증
- 기존 보고의 첫 신청 이벤트 키 `report:requestId`, 미확인 요청에 대한 재보고 이벤트 키 `report:comment:commentId` 두 방식 지원
- 수신자는 DB 큐에서만 결정; 클라이언트는 업무 ID만 전달
- 공용 `push-core.mjs` 조건부 발송 점유를 그대로 사용하여 예약/즉시 발송의 중복 방지 유지
- 즉시 발송 실패 시 1분 주기 예약 발송 계속 유지
- 기존 업무·근태·식사·사용자 역할·RLS·운영 SQL 수정 없음

## 검증 결과
- 전체 HTML 내 JavaScript 스크립트 블록 4개 문법 검사 통과
- `push-now.mjs` 및 공용 발송 모듈 자바스크립트 문법 검사 통과
- 가상 Supabase 응답을 이용한 즉시 전송 테스트: 최초 보고 / 재보고 각 1회 성공(HTTP 204)
- 가상 인증 실패(401), 미등록 요청/댓글 부재/보고 내용 불일치(403): 전송 없이 거부
- 마감시간 화면 변경이 개발 HTML에 유지된 것 확인
- 운영 `main`과 Netlify 운영 배포 변경 없음

## 미검증 및 실제 테스트 필요
- 실제 Netlify `push-now` 함수 배포/동작 및 로그 확인 필요

- 앱 로그아웃 및 화면 꺼짐, 여러 기기 동시 구독, 알림 중복 노출 확인 필요
