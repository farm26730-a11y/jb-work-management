# JB 업무관리 V1.3 — 업무 지시·댓글·보고·휴무 알림 연결 점검 (2단계)

점검일: 2026-11-08. 운영 Supabase 구조 **읽기 전용** 확인, GitHub 시험 브랜치 검토. 운영 변경 및 실기기 푸시 테스트 없음.

## 확인된 서버 연결

- 신규 업무 INSERT: `jb_push_task_insert_v34` 트리거가 배정 직원으로 푸시 큐 등록 (작성자=담당자일 때 제외).
- 신규 업무 INSERT/담당자 변경 UPDATE: `jb_track_task_assignment_v13_trigger`가 직원 확인 요청 테이블에 기록. **UPDATE는 푸시 큐를 등록하지 않음**(문제).
- 댓글 INSERT: `jb_task_comment_notify_insert_v13`가 현재 활성 담당자(댓글 작성자 본인 제외)에 새 댓글 확인 요청 + comment 타입 푸시 큐 등록.
- 업무 보고 INSERT: `jb_push_report_requests_insert_v14`가 보고 대상 역할에 따라 푸시 큐 등록. `jb_submit_report_core_v14`도 보고 푸시 큐를 생성하지만, 이벤트 키/수신자가 같으면 `jb_queue_push_event`의 충돌 무시 조건으로 중복 보관을 줄임. **부서 구분 없는 관리자 전사 수신은 사용자 의도에 따라 유지**.
- 휴무 신청·변경: 기존 트리거를 통해 leave 타입 푸시 큐 등록, 관리자 전사 수신은 사용자 의도에 따라 유지.
- 앱 `index.html`: 직원 홈 신규 업무 확인과 담당자 새 댓글 확인, 20초 조회 포함.
- 기존 현황: 운영 DB 업무 12건, 댓글 8건, 신규 확인 테이블은 각각 0건. 실사용 시나리오를 아직 관찰할 수 없음.
- 푸시 등록 장치: 4건 / 직원 3명. 이는 실기기 알림 성공을 의미하지 않음.

## 확인한 문제
**A. 담당자 재배정 시 푸시 누락**
- 기존 업무에서 담당자만 바꾸면 새 담당자의 확인 요청 레코드는 생성됨.
- 신규 업무 푸시는 INSERT 전용 트리거라 UPDATE에는 동작하지 않음.
- 새 담당자가 앱을 열어야 알림을 확인하는 상태.
- 해결안: `jb_track_task_assignment_v13()`의 **담당자 변경 UPDATE 분기**에서만 별도 고유 이벤트 키의 task 타입 푸시를 큐에 등록.
- 설치용 SQL 시험 초안: `JB_V1_3_업무담당자_재배정_푸시알림_시험.sql`.
- 초안 시간식 `pg_catalog.extract(... from ...)`은 점검 중 PostgreSQL 문법 오류가 발견되어 `EXTRACT(EPOCH FROM ...)`으로 수정, 읽기 전용 SELECT 표현식 정상 실행 확인. **전체 함수 설치·실기기 검증은 아직 하지 않음**.

## 유보 사항
- 기존 업무를 완료 처리하면 미확인 업무 배정 레코드는 DB에 남을 수 있지만 앱 홈에서 완료된 업무를 제외하므로 노출되지 않음. 추후 데이터 정리 정책 검토.
- 댓글 수신 대상은 현재 **업무 담당자만**. 업무 작성자/관리자까지 댓글 푸시를 보내려면 별도 운영 요구사항 확인.
- 관리자·대표자의 새 업무 확인 요청 표시 여부는 현재 직원 위주 로직이며 기존 운영 동작을 유지.
- 기존 푸시 30분 초과 발송 제외는 시험용 GitHub 코드에만 반영, 운영 미배포.
- 중요: 부서별 관리자 제한 SQL은 사용자 의도와 불일치하므로 사용 중단 표시하였으며 적용 금지.

## 적용 전 테스트
1. 새 업무 지시: 생성 푸시 1회 + 직원 확인 요청 1건.
2. 기존 업무 담당자 A→B: B에게 신규 확인 요청 + 푸시 1회, A에게 새 푸시 없음.
3. 동일한 직원에게 다른 필드만 수정: 신규 확인 요청·푸시 생성 안 됨.
4. 자기 업무 생성/관리자 본인 배정: 기존 자기 알림 제외 정책 유지.
5. 댓글: 타인 댓글 한 건에 담당자 확인 요청 + 푸시 1회, 자기 댓글은 제외.
6. 댓글 확인: 서버 확인 시간 기록 및 내부 읽음 동기화.
7. 보고 요청: 대표/관리자 목적지에 따라 알림 생성, 불필요한 중복 없음.
8. 휴무/변경: 관리자 전체 알림 등 의도된 전사 동작 유지.
9. 30분 이상 늦어진 푸시: 기기 신규 등록 직후 몰아서 전송하지 않음.
10. Galaxy 화면 꺼짐/브라우저 종료 상태 실제 알림 수신 및 인증 유지 확인.
