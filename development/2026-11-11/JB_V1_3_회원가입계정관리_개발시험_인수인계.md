## 사용자 문제
회원가입한 직원 계정을 잘못 연결했거나 인증되지 않은 상황에서 Supabase 관리자 사이트에서 계정을 삭제하고 재가입하는 일이 번거롭다. 직원관리 안에서 본인이 계정 상태 확인, 인증 메일 재발송, 연결 해제·재연결, 안전 삭제할 수 있기를 희망.

## 개발 반영
- 기존 앱 직원관리 화면의 "회원가입 계정 관리" 접기·펼치기 패널 추가.
- 인증된 계정/미인증 계정, 연결 직원 이름·상태 표시 및 목록 새로고침.
- 미인증 계정의 인증 메일 재발송(Supabase Auth 및 기존 Resend SMTP 사용), 60초 미만 요청 서버 거부.
- 직원 **로그인 연결 해제**: `jb_employees.auth_user_id`를 NULL로 변경하며 직원·업무·근태 기록은 보존.
- **기존 직원에 재연결**: 인증 완료 계정에 한해서 `auth_user_id`를 기존 미연결 직원 기록과 매핑. 새 직원 생성이 아니라 기존 기록 복구.
- **가입 계정 삭제**: 대표(owner)만 가능; 보호 계정/본인 계정 불가; 연결 계정은 먼저 연결 해제; 정확한 이메일 재입력; 식사 감사 기록 참조 검사; Supabase Auth Admin API `deleteUser` 호출. 데이터베이스 직원·업무·근태 기록을 삭제하지 않음. Storage 소유 객체 등이 있으면 API 오류로 중단 가능.
- 관리화면을 여는 사람은 반드시 **현재 서버 로그인 사용자**, 그리고 **현재 재직 중인 owner/manager 역할**인지를 매 API 요청마다 서버에서 검사. manager는 staff 또는 미연결 계정만 조회·관리, owner는 전 계정 조회 가능하지만 본인/owner 계정 읽기 전용. staff는 API 403.
- 로그인 계정을 바꿔 접속하면 이전 계정 관리 화면의 목록 캐시 초기화.
- 계정 관리용 서버 비밀키는 Netlify Functions 안에서만 사용하며 브라우저 HTML에 내장하지 않음.

## 권장 실제 시험
1. 개발 브랜치 배포 미리보기 혹은 시험 환경 Netlify에서 계정관리 화면 확인.
2. 대표 로그인 → 전체 계정 목록(본인은 보호 읽기 전용).
3. 관리자 로그인 → 일반 직원·미연결 계정만 보임, 대표/관리자 계정은 숨김.
4. 직원 로그인 → 계정관리 불가, 직접 함수 호출도 403.
5. 미인증 시험 계정 → 메일 재발송 → 인증 완료.
6. 업무 이력이 없는 일반 직원 시험 계정 → 로그인 연결 해제 → 동일 직원 기록에 재연결 → 본래 업무 이력 유지.
7. 삭제 시험은 **업무 이력이 없는 별도 테스트 계정**으로만 하고, 삭제 이후 재가입·재연결까지 확인.
8. Auth 삭제가 Storage 객체 소유권으로 막힐 때 이유를 확인하고 임의로 Storage를 지우지 않음.
9. 서비스 역할키 및 사용자 개인 이메일 등은 화면 공유·로그에 공개하지 않음.

## 주의
- 기존 직원을 완전 삭제하는 버튼과 회원가입 Auth 계정 삭제는 별개다. 후자는 직원 기록을 삭제하지 않는 것이 핵심.
- 테스트 스크립트로 운영 계정을 삭제하거나 auth.users에 직접 DELETE SQL 실행 금지.
- 이번 변경은 사용자 배포 요청이 없는 한 `main`에 병합하지 않는다. **버전 V1.3 유지.**
- 복잡한 계정 삭제의 경우 조건을 만족하지 않으면 안전상 거부하고 원인을 보여준다.
