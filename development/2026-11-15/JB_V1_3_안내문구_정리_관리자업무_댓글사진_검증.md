## 사용자 요청 — 앞으로 유지할 원칙
1. **앱 화면에 개발 과정의 정보·시험/디버그 메시지·환경변수·RPC/테이블 구조·버전 내부 설명을 넣지 않는다.**
2. 사용자가 기능을 수행하기 위해 꼭 알아야 하는 정보만 짧게 보여준다.
3. 개인정보·인증·연차 미확정·삭제 위험 등 **실제 안전과 정확성에 필요한 경고는 유지**한다.
4. 상세 설계·시험 내역은 앱이 아니라 GitHub `development/` 기록에 보관한다.
5. 다른 직원/다른 부서/관리자 자신의 업무라도 **활성 직원은 모두 그 업무에 댓글 및 그 댓글의 사진 등록 가능**. 업무 담당·등록자·부서 일치 조건을 댓글/댓글 사진에 추가하지 않는다.
6. 다른 사람이 쓴 댓글의 **수정·삭제·첨부 사진 추가 권한은 별도 보호**(본인 댓글에 추가 가능, 댓글 작성자 본인 확인).

## 실제 오류 확인
- 이전 운영 Storage 사진 업로드 함수 `jb_photo_can_upload`은 대표, 업무와 같은 부서의 관리자, 업무 담당자만 허용. 직원이 관리자 자신의 업무에 댓글을 달아도 사진 업로드가 막힐 수 있음.
- DEV에는 이전 작업에서 별도 댓글 사진 경로 `taskId/comments/commentId/file.jpg`, 본인 댓글 작성자 확인 함수 `jb_comment_photo_can_upload_v13`, Storage 및 `jb_task_images` INSERT 정책 적용 완료.
- 본인 댓글 사진 등록에는 **업무 담당자·작성자·부서 일치 필요 없음**. 댓글 작성자와 해당 댓글의 업무 ID가 정확히 일치하는지만 검사.
- 기존 댓글 입력창은 `required` 텍스트 내용 때문에 **사진만 선택해도 댓글을 제출할 수 없었음**. 이번 수정으로 파일만 선택해도 텍스트 본문을 `사진 첨부`로 자동 입력해 댓글과 사진이 함께 연결됨.
- 빈 글+빈 사진은 등록 거부, 글만 있는 댓글도 기존처럼 처리.

## 수행한 검사
1. JB-DEV **실제 DB 트랜잭션/RLS 시험 통과**:
   - 임시 manager+staff auth.users 생성(트랜잭션 안에서만)
   - 관리자 생성·관리자 본인 담당 업무, 일반 직원은 **다른 부서**
   - staff JWT/role로 해당 업무 댓글 INSERT 성공
   - 해당 댓글에 대한 `jb_comment_photo_can_upload_v13` TRUE
   - 관리자 자신의 댓글에 직원이 사진을 올리려는 경우 FALSE
   - 직원이 해당 업무의 '일반 업무사진' 업로드 권한은 FALSE (다른 기능 권한 유지)
   - 본인 댓글에 대한 `jb_task_images` INSERT (RLS 적용) 성공
   - 마지막 ROLLBACK; 이후 Auth 0, 실제 업무 0, 댓글 0, 사진 0, 연결 계정 0 확인
   - **Storage HTTP 실제 파일 업로드는 아직 검증하지 않았으므로 이 점을 성공으로 주장하지 않는다.**
2. 앱 HTML 내 인라인 JS 4개 구문 검사 모두 통과.
3. 직원이 관리자의 본인 업무를 홈에서 열었을 때 댓글 입력과 첨부 입력이 노출되는지 렌더 모의시험 통과.
4. 본문 없이 사진만 있는 댓글(직원·관리자·대표 3종) 저장 후 해당 사진을 **새 댓글의 정확한 ID**로 업로드 호출하는 모의시험 통과.
5. 글+사진 모두 빈 요청 거부, 텍스트만 댓글 저장 모의시험 통과.
6. 사진 첨부 총 5장 한도, 댓글 사진 경로 분리, 관리자 보고 댓글 정확한 ID 반환 함수는 이전 개발 작업에서 검증.
7. 개발 Netlify `https://shiny-lollipop-c8c0fb.netlify.app`가 development-test 자동 배포 설정된 것은 이전 스크린샷에서 확인했으나, **이번 마지막 커밋이 Published 되었는지 직접 확인 불가**.
