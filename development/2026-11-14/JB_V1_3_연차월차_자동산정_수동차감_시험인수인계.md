# JB 업무관리 V1.3 — 입사일 기준 연차·월차 자동 산정 / 관리자 수동 차감

작성일: 2026-11-14. 운영 반영 여부와 개발 범위를 반드시 구분.

## 1. 사용자 요구
- 연차·월차 발생일수는 입사일 기준 자동 계산. **매월/매년 발생분을 관리자가 승인하거나 직접 적립하지 않음**.
- 관리자 필요시 잔액에서만 수동 차감(사유 기록). 승인된 연차·반차 사용분과 중복 차감 금지.
- 실제 운영 Supabase `bnonnvgtbukztfhaxgrr`의 현재 DB 구조와 데이터 기준. GitHub **development-test만** 코드 수정; main은 운영본 유지.
- 직급 권한: 대표는 전체 직원(대표 본인 연차 제외), 부서장은 본인 및 자기 부서 일반 직원 조회; 일반 직원은 본인만 조회. 타 부서 수동 차감 금지.

## 2. 법정 산정 기준과 예외
- 법정: 1년 미만 매월 개근 시 1일(최대 11), 1년간 80% 이상 출근 시 15일, 3년 차부터 2년마다 1일 가산, 연간 최대 25일.
- 날짜가 지나면 조회 때 자동 재계산함(**저장된 적립 행을 매일 새로 입력하는 방식이 아님**). 매월/매년 승인·확정 화면 제거.
- **중요**: 현재 운영 `public.jb_attendance`가 0건으로 개근/출근율 검증을 자동화할 근거가 없다. 자동 계산은 **잠정 수치**로 표시. 실제 법정 발생/소멸은 근태·휴직·법정 출근 간주·80% 미만 예외 검토 필요. 근태 데이터 0건을 결근 0건으로 확정하지 않음.
- 기존 `jb_hr.annual_leave_grants_v13` 수기 발생 6건을 자동 산정액에 **추가 합산하지 않음**(이중 지급 방지). 기존 원장은 삭제/수정하지 않음.
- 입사일이 없으면 자동 산정 불가(미등록 표시).
- 승인 완료된 하루 연차 1일/반차 0.5일은 `jb_leave_requests`에서 자동 차감. 다일·연차주기 경계가 있으면 별도 사용일수 재확인 후 계산.
- 수동 차감은 기록이 남고, 관리자가 기존 차감 내역을 취소할 UI는 아직 없음. 기록 정정 절차 별도 필요.
- 윤일 입사자의 비윤년 2/28 주기 경계는 Postgres `age`/주년 날짜 계산 차이 때문에 `needs_calendar_review`로 차감 중단 및 노무 검토 대상으로 구분.
- 2026-11-14 기준 적용법: 근로기준법 제60조. 2027-06-10 시행 예정인 시간단위 휴가 제도는 현재 기본 구현 범위 밖.

## 4. 운영 Supabase 적용 내용
**기존 장부/승인·초기화 함수와 데이터에 대한 수정 없이 신규 RPC만 추가.**
- `public.jb_annual_leave_auto_overview_v13()`: 기존 권한별 연차 조회 결과를 사용해 월/연 입사일 기준 발생일수와 잠정 잔여 재계산. 6건 기존 발생 이력은 중복 계산하지 않음.
- `public.jb_annual_leave_deduct_auto_v13(uuid,numeric,text)`: 0.5일 단위, 0.5~25일 범위 수동 차감만 허용. 사유 4자 이상, 잔여보다 과차감 금지, 동시 차감 잠금. 기존 `jb_annual_leave_adjust_v13`를 음수로 호출해 권한과 감사 기록 재사용.
- `public.jb_annual_leave_auto_check_request_v13(uuid)`: 승인 전 입사일 기준 잠정 잔액을 재확인. 미래일·다일·주기 경계는 별도 검토.
- `public.jb_annual_leave_auto_review_request_v13(uuid,text,numeric,text)`: 기존 회사 전체 승인 함수 내 보안 검증을 그대로 통과하면서, 잠정 자동 산정 범위 내에서는 발생분 확정 사유를 매번 수동 입력하지 않아도 승인 처리 가능. **휴무 신청 자체의 기존 관리자 승인 규칙은 유지**.
- 신규 함수 모두 `SECURITY INVOKER`, `anon` 실행 금지, `authenticated`만 실행 허용.
- Supabase 설치 migration:
  1. `jb_v13_auto_accrual_schedule_deduct_20261114`
  2. `jb_v13_auto_accrual_review_gateway_20261114`
  3. `jb_v13_auto_accrual_leap_boundary_guard_20261114`
- 중간에 윤일 예외 SQL `pg_catalog.extract` 문법으로 1회 설치 실패 → 올바른 `EXTRACT(... FROM ...)`로 수정하고 성공. 기존 함수 삭제/변경과 데이터 삽입 없음.

## 5. 실제 운영 DB 조회·시험 결과 (조회시점 수치는 이후 변동 가능)
- 직원 17명, 활성 15명. 대표 제외 연차 조회 대상 14명.
- 입사일 등록 2명, 미등록 12명.
- 근태 `jb_attendance`: 0행. 연차 수기 발생 장부: 6행. 승인된 연차/반차: 총 2건. 수동 조정: 0행, 다일 사용 스냅샷: 0행.
- 대표 인증 컨텍스트로 새 자동 조회: 14명 범위, 등록 2명 잠정 계산, 미등록 12명 상태 분리.
- 직원 권한 조회: 본인 1명만. 관리자 조회: 해당 시험 계정 3명(본인 관리자 1명, 나머지 소속 직원), 대표 0명. 권한 분리 확인.
- 기존 승인된 실제 연차 2건 읽기 전용 사전 확인: 1건 `ready_auto_provisional`, 1건 미래 일자 검토 `future_request_review`. 승인/삭제/차감 실제 실행하지 않음.
- 달력 수식 7개 가상 사례 검증 통과: 입사 전 0, 1개월 1, 11개월 11, 1년 15, 3년 16, 11년 20, 36년 25.
- 전체 HTML 인라인 스크립트 4개 구문 검사 통과.
- 새 함수 4개 `anon` 실행 금지, `authenticated` 실행 가능, SECURITY INVOKER 확인.
- **미검증**: 실제 사용자를 로그인시킨 HTTPS API 호출, 실제 차감 기록 생성/복구, 동시 차감 실통합, 브라우저/갤럭시 화면, 관리자 부서 이동, 장기휴가 및 법정 예외.
- **실제 직원 데이터 덮어쓰기/휴무 승인/차감/초기화는 일절 수행하지 않음.**

## 6. 추가 보완 확인 및 위험
1. **관리자 본인 휴무 자동 승인**: 기존 `jb_manager_create_own_leave_v13` / update / delete를 계속 호출하므로 신규 자동 잔액 검사 게이트웨이를 거치지 않음. 관리자 본인 연차·반차 신청 시 차감 검증 우회 가능. 운영 승인 함수는 현 단계에서 변경하지 않았고 별도 안전 래퍼 개발 필요.
2. **실제 근태 판정 불가**: 출근 기록 0건, 직원별 소정근로일/공휴일/휴직·출근 간주 자료 미완비. 현재 표시되는 잠정 발생은 법적 확정 일수가 아님.
3. **운영 기록 전체 초기화**: 기존 `jb_owner_reset_operations_v11`은 휴무 원본을 삭제해 HR 장부와 불일치 위험. 개발본 초기화 버튼을 잠그고 본문 안내를 추가. **운영 main은 기존 기능이 남아 있어 사용 금지 안내 필요**, 안전 스냅샷/복원 RPC 설계 후 재개.
4. **이월·소멸·연차주기 경계**: 기존 수기 발생분/승인 사용분을 주기별로 어떻게 배정할지 정밀 원장 보완 필요.
5. **연차 휴무 승인/취소/변경**: 기본 직원 대기 승인과 기존 관리자의 본인 자동 승인 구분 유지. 사용일수 중복 차감/취소 정정 실계정 검증 필요.
6. **회원가입·Netlify**: 이전 채팅방의 가입 연결 문제, `public-config.mjs` 운영 누락 가능성, 운영 Netlify 게시 확인은 해결된 것으로 간주하지 않음.
7. **기존 보안 진단**: `public.jb_attendance_effective` security-definer view(1건), 기타 기존 RPC 실행 권한 경고 등 변경 전에도 존재. 신규 함수 4개가 SECURITY INVOKER라 추가 권한 확장은 최소화. 사전 영향검토 없이 구함수 실행권한 대량 회수 금지.
