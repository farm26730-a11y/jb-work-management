# JB 업무관리 V1.3 · 연차 관리 (입사일 기준) 개발 인수인계
점검 및 서버 설치: 2026-11-14

## 개발 환경
- **GitHub:** 기능 수정은 `development-test`에만 적용. `main`과 Netlify 운영 사이트는 변경 금지.
- **Supabase:** 사용자 최신 결정에 따라 운영 프로젝트 `bnonnvgtbukztfhaxgrr`에서 기존 직원/근태 데이터를 그대로 사용하며 **추가형 전용 스키마**로 기능 개발.
- 실제 DB 스키마 및 RPC 변경은 운영 중인 앱에서도 즉시 접근 가능하므로 기존 함수·테이블 삭제/변경은 최소화한다.
- `JB-DEV`는 이번 연차 개발에서 사용하지 않는다.

## 법적 기준 및 시스템 처리 범위
- 1년 미만: 매월 개근 시 1일씩(최대 11일).
- 1년 차: 직전 1년 출근율 80% 이상 시 15일, 3년 차부터 2년마다 1일씩 가산, 최대 25일.
- 연차는 법정 요건 충족 시 발생하며 전산 확정 여부가 법정 권리를 결정하지 않는다.
- 현재 근태 데이터는 월별 개근과 직전 1년 출근율을 자동 확정할 만큼 완비되지 않아, 사용자 화면에서 개근/80% 확인 근거를 기록한 뒤 전산 장부에 반영한다.
- 80% 미만 출근의 월 개근분, 휴직·법정 출근 간주, 법정 사용기간/시효, 입사일 말일/윤년, 시간단위·대체 휴무 등 예외는 별도 개발/노무 검토 필요.
- 기초 잔액과 기존 사용 기록은 임의 채우기 금지, 관리자 확인 후 누락/이중 차감 없도록 대사.

## 실제 Supabase 설치 내역

- `public.jb_employees.hire_date date` : NULL 허용, 기존 직원의 입사일은 미입력 상태

  - `annual_leave_adjustments_v13` : 이전 사용분·기초 잔액 조정 사유 기록
  - `annual_leave_usage_v13` : 다일 연차 차감일수와 원래 신청 기간의 보존 기록
- `public.jb_annual_leave_overview_v13()` : 권한별 연차 현황 조회
- `public.jb_annual_leave_set_hire_date_v13(uuid,date)` : 입사일 관리자 등록
- `public.jb_annual_leave_confirm_grant_v13(uuid,text,integer,text)` : 발생 회차 관리자 확인
- `public.jb_annual_leave_adjust_v13(uuid,numeric,text)` : 사유 있는 조정 이력
- `public.jb_annual_leave_confirm_usage_v13(uuid,numeric,text)` : 연속 휴가의 근무일 확인
- `jb_hr`는 `anon`/일반 인증 사용자 직접 테이블 접근 차단, RLS 활성화, RPC에 로그인/직급/부서 확인.
- 운영 초기화 함수는 **그대로 유지**. `jb_hr`는 `public.jb_*` 테이블 검사 범위 밖에 있으며 삭제 대상(21개)에 포함하지 않음. `jb_hr`에서 초기화 대상 테이블에 FK도 두지 않음.
- 기존 업무/휴무/직원 기록 삭제, 기존 운영 기록 초기화 실행, 사용자의 연차 발생·조정 데이터 입력 모두 하지 않았음.
- SQL 보관본: [설치 SQL](JB_V1_3_입사일기준_연차관리_설치전검토.sql).

## 기존 운영 앱에 미치는 영향
- 신규 `jb_hr` 및 새 RPC는 DB에서 즉시 사용 가능.
- 기존 Netlify 운영 앱은 새 연차 조회 함수를 호출하지 않으므로 연차 UI가 자동 추가되지는 않음.
- 기존 운영 함수는 수정하지 않았음. `jb_employees`에 NULL 허용 `hire_date` 컬럼만 추가.
- 기존 운영 기록 초기화는 21개 대상을 유지하고, 연차 인사 장부는 보존함.
- 실제 운영 전 다음 시험은 필수: 개발 HTML의 서버 연결 확인, 관리자 실계정 권한, 입사일/연차 발생·차감 정확성.

### 배포 전 중요한 잔여 위험
1. **관리자 본인 휴무 자동승인**은 기존 `jb_manager_create_own_leave_v13`를 사용하므로 새 사전 잔액 검사 RPC를 거치지 않음. 이 경로를 기존 업무에 영향 없이 별도 보완해야 함.
2. **운영 `main`의 기존 휴무 승인**은 계속 기존 RPC를 사용함. 개발본에서 신규 승인 래퍼를 호출해도 운영본은 아직 신규 검사를 통과하지 않음.
3. **연간 출근율 80% 미만**에 대한 매월 개근 연차 발생 및 법정 출근 간주(휴직 등)는 전산 자동판정 미구현. 확인되지 않은 발생분은 0일로 단정하지 않음.
4. **연차의 실제 소정근로일/휴일/시간단위**가 직원별로 입력되어 있지 않음. 다일 연차 차감은 관리자의 확인 입력으로만 처리.
5. **승인된 휴무 변경/취소**는 기존 RPC가 실행됨. 날짜 변경 시 이전 연차 일수는 무효화하고 재검토하도록 했지만, 운영 실계정과 휴가 재계산 회귀시험이 필요.
6. **운영 기록 전체 초기화**에서 `jb_leave_requests`를 삭제하되 `jb_hr` 인사 장부는 남는 구조. 1일 연차 사용 내역이 원본 신청 테이블에만 남아 있으면 초기화 후 잔액이 과대 표시될 수 있음. 초기화 전 스냅샷/사용 이력 보존 기능을 설계하지 않는 한 HR 잔액이 있는 상태에서 초기화 실행 금지.
7. 여러 연차 발생 회차가 겹치고 일부가 만료되는 경우, 법정 원장과 다를 수 있으므로 **이월·소멸·사용 회차별 배정** 기능 검증 전 정밀한 확정 잔액으로 단정하지 않음.
8. 신규 스키마의 별도 RLS와 명시적 차단은 적용했지만, 전체 앱의 오래된 보안 경고는 이번 연차 범위 밖이며 별도 정기 점검 필요.

### 2026-11-14 최종 화면 보완과 추가 주의
- 근태의 `휴무·연장근무 조회` 내 버튼은 `jb-chosen` 스타일로 선택 상태 표시. 연차 선택 때 날짜 필터와 일반 휴무 신청 목록을 숨김.
- 연차·반차 신청 종류를 선택하면 **본인의 전산 확정 잔여 상태**를 참고 문구로 표시. 잔액이 미확정이어도 신청 자체는 차단하지 않음.
